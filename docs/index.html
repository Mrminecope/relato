Designed around consent.

The product direction is intentionally simple: public discovery should not mean public exposure, and AI-assisted context should never be presented as identity proof.

01 / CONSENT

Explicit public-source context

OSINT is limited to lawful public sources and user-consented identities or handles. Private accounts, bypasses, and silent identification are outside the product boundary.

02 / PRIVACY

Public projection, private profile

Discovery is intended to expose only approved public fields. Email addresses, privacy controls, and connection-lock state stay private.

03 / AI

Compatibility is an estimate

Gemini-assisted analysis can describe affinity and conversation context, but it is not identity, authenticity, or trust verification.

Safety is enforced at the data layer.

Relato’s security architecture separates client experience from trusted lifecycle operations so sensitive invariants do not depend on React alone.

Age separation16–17 is friendship-only; dating requires both participants to be 18+; adult/minor connections are rejected.
Dating exclusivityThe one-active-dating-connection rule is designed to be enforced atomically when a request becomes a match.
Mutual acceptanceRequests are accepted or declined by the recipient, cancelled by the sender, and chat access is restricted to active match participants.
External emailGmail communication is opt-in. Minors remain inside Relato and personal email addresses are not exposed through discovery.
Built for calm discovery, not surveillance.

Relato keeps OSINT as a core capability while applying a clear boundary: lawful public information, explicit consent, transparent provenance, and no claims that an AI score proves who somebody is.
